# AgentClub 开发 SOP

目标：每个需求有可体验的结果，每次检查和审阅能对应准确版本，各开发任务与日常数据互不干扰。
命令实现是执行真相：环境配置在 config/environments.json，检查清单在 scripts/checks.py，
GitHub 规则与当前提交状态决定能否合并。本文描述协作方式，不复制另一套门禁实现。

## 一条交付链

需求与验收条件 → 隔离开发 → 作者自验 → PR/按风险审查 → 合并 → alpha 核对 → 单独发布。

| 状态 | 必须能拿出的事实 |
| --- | --- |
| 待定义 | 问题、用户期望、范围与可观察验收条件；重大歧义先问清 |
| 开发中 | 从主线创建的任务分支/独立环境；跨组件工作有简短实现计划 |
| 待审阅 | 真实入口、结果或截图、准确提交与检查证据、剩余限制 |
| 已合入 | GitHub 上实际合并到 main 的提交，不把 CI 绿当成合并 |
| 已验收 | alpha 对合并结果走过关键用户路径，检查原验收条件 |
| 已发布 | 日常实例身份与 current.json 一致，记录 CI 验证 head、合并/部署 SHA、前版及备份 |

实现完成、检查完成、已合入和已发布是不同状态。已确认方向内自主推进；遇到真正阻塞
或目标/范围出现分歧时带具体结果沟通，不在每个小步骤反复询问是否继续。用户不承担首轮 QA。

## 开始与实现

先看环境状态和现有任务。小 bug 在 Issue/PR 写清触发、预期和验收即可；跨组件、状态或
协议变更在 docs/plans 写计划，说明依赖、顺序及恢复边界。避免每个文案修改增加整套文档。
一任务一分支一 PR，使用 env.sh dev 创建 worktree。相关前后端交互在同一任务内闭环，
不能仅以“组件已写好”或“测试数增加”代替用户结果。

日常开发先跑受影响检查；新行为和 bug 用能观察真实失败的最低足够测试层级。
真实 CLI 的启动、认证、MCP 提交和最终展示需要真实闭环证据，演示 UI 或 --version 不可替代。
真实调用单独 opt-in，不把本地账号和日常数据搬到验收环境。

## 按风险选验证和审查

| 风险 | 开发期验证 | 合并前审查关注点 |
| --- | --- | --- |
| 文案、样式、普通文档 | 内容核对；界面变更展示实际截图 | 是否符合原要求、是否引入体验问题 |
| 局部行为、bug | 受影响测试、类型/构建、真实入口自验 | 用户结果与回归边界 |
| Provider/MCP/SSE/调度/重试 | 契约与消费者、失败路径、必要集成 | 非作者核对共享语义与兼容性 |
| 数据、凭据、权限、迁移 | 正反向边界、持久化与恢复验证 | 非作者审查数据/安全影响 |
| 启动、门禁、审批、发布工具 | 故障/竞态/归属/恢复证据 | 门禁调整按所有者明确授权；保留其余保护并回读验证 |

独立审查默认一个合适的非作者；存在不同风险才叠加视角。实际参与者与所用证据如实记录。
这些分组决定开发期关注点，不自动删除现有 CI 覆盖。CI 和 release-check 使用相同检查
清单；完整 all 包含依赖审计，不能静默跳过红灯。

## PR 与合并

PR 写清问题与最终行为、验收证据、风险、恢复方法和实际协作者。提交中保留真实人类
Git author，Codex 实质参与使用规定的 co-author trailer。未发生的 reviewer 或人工验收不得预填。

`./scripts/release.sh prepare --pr <编号>` 从 GitHub 读取当前 head、CI、基分支与候选审阅就绪状态。
不再要求 Owner release 或 Owner approval。两项 CI、适用审阅、对话解决和分支规则均满足后，
所有者决定合并。新增提交重新运行 CI，受影响的审阅重新核对；正文不能代替实际检查或审阅。

连续 PR 可以暂时以父功能分支为基线，CI 仍运行；必须先合并父 PR，再将下一 PR 改基到
main、处理 squash 后的差异并重新验证/审阅，不能把“合并到父功能分支”记成已交付主线。
当前流程改造依赖顺序为 PR #22 → PR #23 → PR 3。

## 合并后、发布与复盘

作者在 alpha 同步后的准确 main 提交上复验关键路径，说明成果、差距及下一步。方向改变
才重新校准，不把每次同步当成新增审批。收尾逐项核对需求与验收条件，保留真实未验证边界。

发布是独立动作，操作细节见 RELEASING.md。stage 准备已合并且 PR head 的必需 CI 成功的不可变候选；
activate 才切换日常实例，须由所有者明确执行。保留当前/前版、状态备份和转换记录。
首次迁移旧服务先完成工作、由所有者停止旧实例，再显式导入；绝不把空库当成迁移成功。

事故用“触发—影响—证据—原因—修复—防复发”记录，并把可重复防护落实到脚本、接口或检查。
已合并分支和 worktree 先核对提交、未提交/被忽略的有价值数据及运行占用，再单独整理。
本批 PR 不执行历史目录清理或日常数据迁移。
