# 共享开发任务与自主推进约定

状态：历史实验方案，已由[自适应多 Agent 自主推进 Spec](2026-10-23-adaptive-agent-autonomy-spec.md)替代。下文保留旧实验的设计与验收范围；已有实现和离线检查不代表满足新 Spec。

## 原始需求

参考 Clowder，让不同角色自主推进任务：先把需求变成可追溯的开发约定；用共享任务保存责任和进度，避免聊天结束后工作丢失；保留证据，审核绑定具体需求和代码版本。

## 设计依据与落点

参考本地 `../clowder-ai` 的 TaskStore（共享责任、线程关联）以及 request-review 的原始需求、自检证据、独立审核设计，不直接复制其运行栈或角色体系。继续复用本项目 SQLite、MissionRunner、Provider Router 和宿主注入的 MCP 身份。

开发约定和共享任务独立于一次 mission；conversation 是工作范围，mission 是一次执行尝试。人格保持不变，执行人和审核人由每张任务明确分配。开发约定先形成草案，再由用户在任务板启用，启用后按依赖自动执行、验证、审核、返工。任务结束不等于开发完成。

## 验收条件

- AC-1：保存原始需求、目标、范围、非目标、可编号验收项和验证命令；约定修订追加新版本，保留旧版本与审核。
- AC-2：共享任务包含约定版本、验收项、唯一责任人、独立审核人、依赖、进度、阻塞原因和执行历史；SQLite 重建实例后仍可读取。
- AC-3：明确启用后自动调度可执行任务和审核任务；依赖未完成不调度；同一工作板一次只执行一个任务；并发领取不重复启动。
- AC-4：MCP 从宿主上下文获取身份与 mission，禁止冒领、自审和过期执行写回；普通聊天不能替代任务状态。
- AC-5：提交时由宿主执行约定中的验证命令，保存输出、退出码、摘要哈希、验收项、约定版本、Git HEAD 和执行来源；失败不得进入审核。
- AC-6：审核针对确切约定、验收项、证据和提交 SHA；HEAD 变化或工作区有未提交改动时不能批准；保留旧审核，并显示其适用版本。
- AC-7：失败、缺少结构化交付、预算耗尽、进程中断均留下阻塞记录；重启不重放未知的文件副作用；用户可显式重试。暂停在回合边界阻止新任务。
- AC-8：前端可编辑约定、分派任务、启用/暂停、查看责任和证据并重试；后端协议、恢复和并发行为有离线测试。

## 边界

首版执行当前服务所在 Git 工作区，串行调度避免多角色同时写同一工作树；用户通过明确标注的启动按钮授权任务范围内的本地提交，不自动合并或发布。代码工作区必须已有提交且提交验证/审核时干净。演示 Provider 不生成虚假测试和审核结果。重启保留状态并阻塞未完成的执行，由用户显式重试。已完成任务的审核仅证明记录中的 SHA，不推广到后续提交。
