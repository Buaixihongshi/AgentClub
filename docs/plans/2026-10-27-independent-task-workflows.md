# 独立任务与可选 Workflow 编排

用户要求任务与会话分离，并确认同时保留模板/自定义编排与 AI 自主编排。布局参考用户草图：左侧窄导航（会话/任务）、中间对应列表、右侧对话或任务详情；保留 Unity 现有纸白、鼠尾草绿、描边与硬阴影。

## 用户结果

- 未选择会话也能进入任务列表并直接新建；会话里确认的任务会自动出现。
- 新任务先保存为未开始，明确开始后才准备环境与执行。创建时可选自主编排或编辑步骤（目标、负责人、前置依赖）；执行前可修改，开始后规划锁定。
- Workflow 根据持久定义与真实执行状态显示，子步骤完成后仍由根负责人集成验收。正式独立审核沿用原候选与证据机制，不把普通“审核”步骤伪装成正式审核。
- 会话保留提议确认与紧凑进度链接；任务管理、决定、交付和预览在独立入口。切换保留聊天草稿与任务编辑草稿。

## 实现契约

新增 `/api/tasks` 列表与创建、`/api/tasks/{root_id}` 详情和 commands；根 `wt_` 是用户任务 ID，原 mission 仅为一次执行。新任务内部使用隐藏 kind=task 的执行会话，来源会话单独关联；旧任务无需迁移即可投影。详情/命令限制在 URL 指向的同一根任务，日志/快照仍复用原有安全范围。

编排 mode 为 adaptive/workflow；step 为 `{id,title,owner_id,goal,depends_on}`，响应由宿主补充真实 task_id。输入验证角色、唯一 ID、依赖存在、自依赖与环；步骤子约定继承授权范围与风险，根依赖全部计划步骤。配置、领取和幂等必须原子，环境准备在事务外。

保留累计预算、版本化约定与内容快照、用户独占批准、只读审核、恢复核对和持久调度。当前执行仍保守串行，图中的分支表示依赖关系，不暗示同时执行。

## 分工与验证

Codex 主代理负责全局布局、导航、会话拆分、集成与浏览器核对；后端代理实现资源/编排/权限与回归；前端代理实现任务列表、Workflow、表单与行为回归。集成后进行非作者复核，实际结论记录，不预填通过。

回归重点：独立新建/刷新/幂等，内部执行上下文不混入会话，跨根命令拒绝，DAG 顺序与根验收，规划锁定、预算和暂停恢复，旧任务兼容；切页保草稿、提议确认与任务跳转、旧响应不覆盖新版本、窄屏可达。演示不冒充真实模型开发或审批，预览与日常数据隔离，不部署日常实例。

## 编排编辑界面调整

- 原长表单改为步骤导航与单步编辑，窄屏使用横向步骤导航；调整编排弹窗保留固定操作栏。
- 两种编排方式共用本地 `TaskOrchestrationForm`，切换模式保留流程草稿。新建任务复用同一编辑器。
- 复用现有 React、Lucide、`WorkDialog` 及浏览器原生表单控件；未增加 UI 套件、表单库或流程图依赖。组件源代码随仓库维护，样式使用项目已有色彩与表面变量。
- 验证步骤切换、模式往返、增删步骤后的依赖清理，以及未选中步骤的完整性检查；服务端协议与启动条件保持原约束。

## 控件样式一致性

- 任务筛选使用本地 `UnitySelect` 封装，统一触发器和弹层样式；交互交给精确锁定版本的 `@radix-ui/react-select`，不引入整套 UI 框架或第二套图标、表单库。
- 工作区预览操作复用 `work-primary`，统一状态展示、开始/停止/打开预览控件。
- 会话编辑区与外框同宽，发送按钮定位在编辑区内部；为按钮预留底部空间，保留原有提及补全、输入法及发送行为。
