# 网页任务的独立工作区与预览

## 目标

用户在 AgentClub 对话中确认开发提议后，每项独立工作有自己的分支和代码目录；任务页继续展示责任、进度、验收与文件，增加工作区状态、失败重试及可控预览。复用主线提议确认、记忆装配和受管环境工具。

## 范围

- 新根任务在确认后记录环境绑定；提议未确认时不创建工作树。
- 根任务及协作者的读写、快照、检查与交付使用同一绑定目录。
- 独立任务目录互不混用；执行仍串行，页面展示排队原因。
- 准备、重试和预览在数据库写事务外执行；请求幂等并核对 revision。
- 预览通过已有受管环境生命周期启动与停止，数据独立，不导入日常聊天或凭据。
- 旧任务保持原目录语义，不静默搬迁；既有工作树不 reset 或自动删除。
- 不移植已放弃的普通任务回合取消功能，不改变所有者批准或发布门禁。

## 实现顺序

1. 工作区准备、身份核对、重启恢复与绑定持久化。
2. 保留提议确认链，接入调度、验证、快照及发布适配器目录。
3. 在当前任务视图添加环境、排队和预览状态，不恢复旧表单界面。
4. 回归临时 Git 项目、提议确认、并发幂等、失效路径、进程归属与记忆兼容。
5. 运行统一离线检查及浏览器验收，提交独立 PR；按最终 SHA 完成审阅合并后再进行主线 alpha 验收与单独发布。

## 验收

- 两项已确认任务绑定不同目录和分支；重试、协作、刷新与重启继续复用。
- 文件、检查和候选快照来自绑定目录，主控源码与日常数据不被复制为测试库。
- 未确认提议不创建目录；错误角色、旧 revision、重复或冲突 operation_id 正确处理。
- 工作区准备失败可见、可重试，不回退到主控目录；取消任务不再准备新环境。
- 预览可启动、打开、停止及查看失败原因，拒绝停止身份不匹配的进程。
- 当前提议确认、任务双视图及记忆回归继续通过。

## 交付边界

涉及共享调度、MCP 执行目录、持久任务状态和启动管理，需要非作者审阅。真实 CLI 质量和正式发布分别记录，离线检查或演示浏览器结果不作为所有者批准。现有版本保留至新版本通过门禁并准备发布备份。
