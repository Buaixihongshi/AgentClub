# 右侧产物栏

需求：会话旁常驻可收起的产物入口，以当前会话为默认范围，可切到所有活跃普通会话的文件索引。
方案：张楚岚；交互原型：王也；实现与作者自验：冯宝宝（Codex）。实现者不承担独立审查。

## 验收

- A1 当前会话所有 mission 的文件及时显示，与聊天 artifact.saved 卡片一致。
- A2 跨 mission 同名文件保留两条，各自打开正确内容；修复 #86。
- A3 定位卡片并高亮 1.5 秒，停止自动贴底；找不到时明确提示。
- A4 复用查看器，Markdown、代码、HTML sandbox=allow-scripts 与下载行为保持一致。
- A5 全部仓库带会话标签，选择标签切换并定位。
- A6 当前会话搜空后可携关键词穿透全部仓库。
- A7 ≥1440 可固定，偏好保存在本地；窄屏降级抽屉；Esc/遮罩关闭、焦点恢复；收起保留入口。
- A8 索引排除任务上下文、无会话、验证任务及默认归档会话。
- A9 索引只返回 mission 相对路径；拒绝绝对路径、Windows 盘符与父目录片段。

## 实现与偏离

1. 第一笔提交提取 useArtifactContent、导出查看器、隔离 mission:path 内容状态，补失败到通过的回归。
2. 第二笔提交当前会话侧栏与定位。数据直接消费 App 已由 buildConversationTimeline 合并且过滤可见性的 displayMessages，避免另复制 SSE 合并规则。
3. 第三笔提交核心只读 GET /api/artifacts，搜索/分页、全库范围与跨会话定位，以及集成检查和演示证据。

产物属于核心能力，不挂可选扩展。索引在 SQL 内按 mission 与原始 path 取最新事件再分页，避免重复身份跨页和旧标题误命中；相较方案中的页内去重，这是更严格的口径。
请求最多处理 2000 个最新身份记录；达到上限时允许空页带 next_cursor，前端提供继续加载。不新增索引或迁移；SQL 最新身份聚合仍会扫描 artifact 事件，规模大时应测量后优化，2000 上限只限制应用处理量。
所有条目来自保存事件，不扫描磁盘补齐；任务看板的候选版本产物不混入。全部仓库按保存事件序号倒序，页面计数表示已加载结果，不伪装成全库总数。

## 验证与边界

回归覆盖 mission 切换同名内容、时间线合并、搜索与类型过滤、作用域穿透、固定偏好、Esc 优先级；后端覆盖会话隔离、归档、路径安全、去重、分页与搜索。
使用独立 development 的真实 CLI 路由写同名 HTML 和跨会话 Markdown，再用 ego-browser 验证真实显示、定位、下载和三种栏态。检查用 scripts/checks.py 的 frontend/backend/privacy/hygiene，记录最终 SHA 与摘要于 PR。

只提交 PR；跨会话数据范围需非作者审查。未合并、不操作 alpha 或日常实例。恢复通过 revert 本 PR；没有数据库结构变更。
