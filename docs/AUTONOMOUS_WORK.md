# 自适应自主工作

本功能对应[已确认的 Spec](plans/2026-10-23-adaptive-agent-autonomy-spec.md)。角色围绕工作目标选择必要动作；简单任务可以一个角色完成，协作、设计确认和独立审核按需加入。

## 使用方式

1. 在对话中输入 `@` 并从候选列表选择伙伴，然后描述目标。信息不足时先澄清，普通对话不自动获得持续开发或上线授权。
2. 需要持续推进时，角色通过 `propose_work` 保存提议，列明负责人、目标、范围、交付终点和验收条件。对话里出现紧凑的「查看提议」入口；打开可查看详情，选择「确认并开始」或「继续讨论」，不要求用户先填写任务表单。
3. 确认前没有可调度任务。确认引用具体提议 ID、当前 revision 和稳定 operation_id；系统保存人类来源及提议摘要。补充新需求后旧提议失效，同一角色的新提议替代旧的待确认提议。默认提议交付终点为 document，明确开发需求才选 development。
4. 负责人按缺口安排必要动作，使用 `invoke_agent` 创建持久子任务；协作不解除父责任，结果回来后仍由负责人整合验收。角色顺序、多版设计与普通低风险工作的独立审核不是固定流水线；项目规定风险必须由非作者审核。
5. 对话／任务标签分别承载交流和追踪。切换保持草稿和对话节点；任务页展示负责人、状态、待决定事项、重点记录及交付物。默认只显示六项重点记录，其余记录、完整事件与技术依据可展开。历史角色和审核结论不改写成当前配置。
6. 重要选择显示决定卡，HTML、Markdown、图片按需预览。只有单张明确的待决定卡支持聊天回复；模糊、多卡、未回复不会自动批准。生产批准绑定当前交付版本、约定和目标环境，批准不等于实际已上线。
7. 可暂停后续动作、恢复、取消或在高级入口调整已有约定；暂停允许当前回合收尾，取消不撤销已产生效果。关闭或归档会话不清除已经授权的共享工作。任务首页不再用新建工作表单替代对话。

兼容 API 保留显式 `work_mode` 和 `create_work`；这些是外部调用者明确授权的入口，主界面不再要求先选「本次交付」。`/discuss` 保持讨论语义，不获得自主开发授权。历史共享协议仍可查阅，入口说明见 [历史实验](SHARED_WORK.md)。

## 必须区分的交付范围

| 提议交付终点 | 权限与结束条件 |
| --- | --- |
| document · 方案与文档 | CLI 只可写项目 `docs/` 和自己的临时目录；文档完成并有核对依据即可交付，不进入代码实现 |
| development · 开发与验证 | 在指定项目内开发、验证并保存产物；不自动创建 Git 提交、合并或发布 |
| online · 开发后申请上线 | 完成开发与适用审核后等待用户批准；获批版本实际发布并核对成功后才完成根任务 |

首版要求项目位于有初始提交的 Git 工作区。代码可保留未提交改动；宿主将已跟踪文件和未忽略的新增文件保存为可复现快照，供证据、审核和批准引用。单次完整快照上限 32 MB，生成文件和本地配置应由 `.gitignore` 排除。不能只用 Git HEAD 代表存在未提交改动的内容。

## 独立工作区与预览

确认提议后，新根任务自动准备独立分支和代码目录；确认前不创建目录。负责人及协作者在同一任务目录开发，快照、验证和文件交付都引用该目录。不同根任务的代码相互独立，执行动作仍串行；任务页会显示其他工作正在执行的排队原因。

当前默认项目是本服务所属的 Git 仓库，从刷新后的 `origin/main` 创建任务基线；离线时使用已缓存并记录 SHA 的主线。尚无网页选择其他仓库的入口。日常受管实例的任务目录位于环境根的 `features/<任务短编号>/`，alpha 和开发环境使用各自私有状态下的任务目录。准备失败时保留任务、原因和重试入口，不回退到主控代码目录。

在任务页的「工作区与预览」中，可以查看状态、启动预览、打开页面或停止预览。生产预览接入已有受管环境工具，以独立演示数据运行，不复制日常数据库或凭据。暂停任务，或等到当前动作结束且任务等待验收后，再启动预览。准备依赖可能需要时间，失败会保留原因和可用日志；没有受管启动能力的项目会明确失败。

停止预览会核对实例身份和活动状态，不按端口终止未知进程。主控重启后，仍可确认归属的受管预览继续保留；状态未知时要求核对，不自动清理代码。任务页上的预览不等于主线 alpha 验收或正式发布。现有旧任务继续使用原工作目录，不在升级时静默迁移。

## 调度和审核

- 目标、约定、检查点、分工、决定、累计预算和执行历史保存到 SQLite；一次 mission 只是一次必要动作，不等于整项工作。
- 后台根据持久记录调度。丢失一次唤醒、关闭页面或会话被归档，不会清除工作。
- 使用同一工作树的任务串行执行。当前实现也保守地串行安排只读协作，不要求并行才能完成任务。
- 安全/权限、数据持久化语义、迁移、对外契约和调度治理变更要求非作者审核。负责人可以主动增加审核。宿主对已知项目边界做保守检查，不能保证自动识别任意代码中的全部语义风险。
- 协作任务有自己的产物验收项；根任务仍须按原始要求做集成验收。设计产物的作者可以审核另一位角色的代码实现，代码作者不能给自己审核。
- 负责人移交时，宿主先唤起目标角色读取交接材料并明确接收；接收前原负责人持续负责。没有为了内部交接固定增加用户审批。
- 默认最多 20 次 Agent 尝试、同一可安全重试动作最多重试 2 次，连续 3 次缺少可检查进展则等待决定。所有子任务与 Provider 尝试计入根预算，重启不重置。

暂停允许当前动作受控收尾；取消会阻止后续动作并尝试停止当前 CLI，已经产生的效果不会被假定撤销。

## 安全恢复

服务恢复会核对持久记录、工作区快照和旧进程。确认没有产生改变时可自动继续；已有文件变化时安排只读核对，再选择后续动作。旧进程仍可能写入时保持等待，不能只凭数据库领取过期就开始冲突写入。

CLI、验证与发布子进程由宿主看守；宿主异常退出会触发进程组清理。外部发布的结果仍可能未知，此时查询实际状态，不能直接重放发布命令。主动暂停跨重启保留。

## 受限执行与 Provider

首版 CLI 执行复用宿主 MCP bridge 与 macOS `sandbox-exec`：项目读写范围由宿主配置，审核、恢复核对和责任接收阶段只读。模型不取得数据库路径，也不能通过写 `.git` 或 `.agenthub` 直接改变提交历史和发布配置。

支持已配置的 Codex、Claude 和 Antigravity CLI，继续使用原有 Provider 路由、模型配置、超时与上下文导出批准。真实 CLI 接入仍需对应本机环境验证；不支持隔离的平台或不支持工作工具的纯文本 API 会明确阻塞。文档范围和只读范围不会降级成提示词承诺。

仓库保持默认演示 Provider。演示模式会保存工作和责任并明确等待真实连接，不伪造实现、验证或审核通过。自动化验收中的脚本 Worker 只用于验证协议和界面，不能当作真实模型的开发能力证明。

## 项目发布入口

用户在项目 `.agenthub/work.local.json` 中配置自己的受管发布入口，该目录被 Git 忽略，Agent 执行环境不允许修改。示例中的命令是项目自有脚本，不由模型提供：

```json
{
  "release": {
    "environment": "production",
    "command": ["./scripts/deploy-approved-version"],
    "verify_command": ["./scripts/query-deployed-version"],
    "timeout": 300
  }
}
```

宿主执行前核对批准仍指向当前候选及环境，并向两个命令提供：

- `AGENTHUB_CANDIDATE_ID`：完整的获批快照 ID。
- `AGENTHUB_TARGET_ENVIRONMENT`：目标环境。
- `AGENTHUB_RELEASE_ID`：持久发布 ID，可供部署系统去重。

发布脚本须发布这个确切候选，不应自行切换分支或更新到其他版本。实际状态查询命令成功退出，并仅输出如下 JSON，宿主才记录已上线：

```json
{"candidate_id":"ws_完整快照ID","environment":"production","status":"published"}
```

只看发布命令退出码不会显示成功。中断或查询失败后保留日志，后续仅重查实际状态；若确需重新部署，应生成新的明确发布动作与批准，不盲目重放。配置环境或候选变化会使旧批准失效。

## 协议与证据入口

- `GET /api/conversations/{id}/work`：完整工作卡及历史。
- `POST /api/conversations/{id}/work`：用户控制。写入携带 `expected_revision` 与稳定的 `operation_id`；同一操作重试复用编号。
- `GET /api/conversations/{id}/work/logs/{log_id}`：实际验证/发布日志。
- `GET /api/conversations/{id}/work/snapshots/{snapshot_id}/file?path=...`：该会话已保存的文件版本。HTML 预览使用独立来源沙箱，禁止网络和真实表单导航；可运行本地脚本交互，不能把预览当成已连接业务后端。
- MCP `shared_work`：普通对话可 `propose_work` 保存待确认提议；用户通过 `accept_proposal` / `reject_proposal` 处理。执行任务时读取当前工作、整理初始验收、保存检查点、提交产物、请求决定、增加风险与提交审核。较长日志通过 `read_evidence` 分页读取。
- 提交产物必须明确 `kind`：设计候选为 `design`，最终代码为 `code`，文档为 `document`。缺少类型会拒绝提交，避免把设计者误记为代码作者，影响独立审核资格。
- MCP `invoke_agent`：唯一 Agent 间协作入口，产生持久子任务，不从正文点名解析路由。

Agent 不能代替用户批准发布、修改预算或扩大授权。状态与权限检查覆盖 stdio 和宿主 bridge；普通聊天、stdout 或 CLI 成功退出均不能单独关闭工作。

## 历史与验收

旧共享任务保持原有协议；正在执行的旧工作不会静默切换。停止后可以在同一会话建立新工作，旧约定、任务和审核保存在历史中。旧操作说明见[历史实验](SHARED_WORK.md)。
