# 回合失败提示与原生活动

会话和任务详情新增 `failure_events`，由已有回合事件派生，作为独立的系统提示投影到聊天时间线。它们不写入消息表，不进入后续模型对话历史，无需数据库迁移。

- 回合超时或失败后，即使继续发送消息、刷新并重开会话，提示仍然保留。
- 任务结束后才确认失败；同回合的备用 Provider 成功时，不保留失败误报。
- 已发布部分回复的失败回合保留回复，并明确说明已有内容已保留。
- 缺少回合终态事件的任务级故障也显示提示。

Antigravity 启动时使用 `--output-format stream-json`。解析 `init`、`step_update` 和 `result`；仅将工具步骤的开始、完成或失败写为 `provider.activity` 事件。通过现有任务快照、SSE 和会话工具记录传到前端。

前端按 `activity_id` 合并开始/结束事件，显示最新动作摘要并可展开历史。回合失败后，活动列表跟随失败提示保留。MCP 委托调用沿用已有 MCP 工具记录，避免重复显示。

Claude 的 `completed` 事件表示工具参数生成结束，尚不代表工具执行完成；后续 `result` 且 `ok=true` 才显示“已完成”，失败结果显示“未完成”。前端合并结果时保留先前事件的非空摘要和参数，不用空字段覆盖；历史事件也适用此映射，不改写数据库。其他 Provider 的完成状态保持原有语义。

活动摘要只保留工具类别和必要的文件名，不存入工具原始输出、命令参数或模型推理。原生流式文本不被提升为正式回复；正式回复仍要求成功调用 MCP `publish_message`。

## 验证

回归覆盖历史失败在后续消息和刷新后的保留、备用 Provider 成功后消除误报、部分回复保留，以及原生步骤的解析、去重、完成状态和运行期间持久化。
