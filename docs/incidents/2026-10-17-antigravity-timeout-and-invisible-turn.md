# 2026-10-17 Antigravity 超时与聊天回合空档

事故发生于 2026-10-17，排查和修复于 2026-10-18 完成。下列时间均为北京时间（UTC+8）。

## 影响

用户点名王也执行已选定的界面方案，首个任务超时且没有发布回复。用户再次提交相同请求后，新任务成功发布回复。聊天历史只显示两条相同的用户消息及后一轮回复，未解释第一次请求的失败，呈现为王也跳过了一轮。

两条用户消息对应两次独立请求，并非前端重复渲染。首次任务在数据库中仍为 `blocked`，没有丢失已经发布的 agent 消息。本次修复不代表该界面开发任务已经交付。

## 原因

### 单轮预算耗尽

宿主实际预算为 300 秒，适配器把 Antigravity 的 `--print-timeout` 设置为 290 秒，预留退出时间。原生会话持续在读取、检查和测试中推进，尚未进入源码修改或正式发言就耗尽预算；不存在足够证据认定某个单独工具一直卡死。

认证在启动后成功，日志未记录配额耗尽终止。Git 事件监听器另有 `worktreeconfig` 兼容报错，但第二次成功请求也出现同类报错，不能将其认定为本次超时的直接原因。

### 活动不可见

原先启动 Antigravity 使用默认文本输出，应用没有对应的原生流式事件解析器。CLI 内部已执行的文件读取和命令未进入任务的活动记录，因此用户看不到这轮仍在工作。

### 历史失败不可见

会话详情的聊天时间线使用消息记录，前端仅合并当前任务的消息。旧任务的 `turn.blocked` / `turn.failed` 没有形成持久的聊天提示；继续发送或刷新后，失败只留在后台事件中。

## 本次修复

1. 任务及会话详情新增派生字段 `failure_events`，前端按稳定 ID 合并并排序。旧失败记录无需迁移即可显示；后续消息和刷新不会覆盖提示。
2. 等任务终止后确认最终失败，避免备用 Provider 成功后仍误报失败。部分回复已发布时保留已有回复，并说明已有内容已保留。
3. Antigravity 使用 `--output-format stream-json`，解析原生工具步骤，把开始、完成、失败保存为 `provider.activity`。
4. 活动摘要通过现有 HTTP / SSE 快照和会话工具记录传递。前端按 `activity_id` 合并状态更新，展示最新动作并允许展开历史；失败回合仍可查看活动。
5. 不把原生 stdout 升格为正式回复。只保存工具类别和必要的文件名，忽略原始工具输出、命令参数和模型推理。

接口和展示契约见 [回合失败提示与原生活动](../architecture/turn-activity-and-failure-display.md)。
