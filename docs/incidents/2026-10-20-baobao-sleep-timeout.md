## 为什么 42 项工具都显示未确认

数据库共有 42 个原生活动 ID（25 次 Bash、15 次 Edit、2 次 Write），每个 ID 都包含 `started → completed → result`，最后 `result` 的 `ok` 均为 true。

Claude 流解析器在工具输入生成结束时发出 `completed`，收到工具执行结果时再发出 `result`。前端 `buildToolCallsByTurn` 用最新事件覆盖同一 ID 的旧记录，因此最终拿到的 phase 为 `result`，summary 又可能被空值覆盖。`NativeActivity.phaseLabel` 只识别 `completed` / `failed`，把未识别的 `result` 归为“未收到完成确认”。这也解释了列表为什么丢失具体命令说明、只剩 Bash / Edit。

这是活动展示协议不一致，与本轮宿主硬超时是两个问题。成功工具结果也不等于任务完成：本轮只有一次 Hub `log_thought`，没有 `publish_message`，没有 agent 消息落库。
