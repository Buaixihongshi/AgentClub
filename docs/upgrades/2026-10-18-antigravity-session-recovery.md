# 2026-10-18 Antigravity 常驻进程与中断恢复升级

日期以北京时间为准。本次实现依赖 [PR #15](https://github.com/Buaixihongshi/AgentClub/pull/15)
提供的 Antigravity 流式活动协议，以堆叠 PR 提交，不包含讨论模式选择器的界面改造。
代码提交与上线部署分别管理；本记录不代表已合入 main 或已切换生产服务。

## 背景与目标

此前王也的一轮执行在发布正式消息前耗尽单轮预算。排查确认 CLI
仍在读取代码和运行测试，用户页面却没有足够的进度及失败信息。
PR #15 负责补齐这部分可见性；本次进一步解决重复启动开销，以及复用
进程后可能发生的身份串轮、重复发布和进程中断问题。

目标是复用同一会话、同一角色的 CLI 进程，同时让任务进度独立持久化，
在进程丢失时明确识别已完成结果和需要核对的操作。

## 变更内容

| 项目 | 升级后的行为 |
| --- | --- |
| 进程复用 | 使用 stream-json 双向管道，每轮收到 result 后再发送下一轮；最多复用 12 轮，空闲 15 秒回收 |
| 隔离 | 按数据库、产物目录、会话、角色及启动配置划分；切换范围时回收旧进程 |
| 执行授权 | 每轮签发新的 context_token，绑定工作进程、代次、任务、角色、回合、Provider 和截止时间；数据库只保存凭证哈希 |
| 操作去重 | MCP 副作用调用使用稳定 operation_id；同参重试返回原结果，冲突参数被拒绝；每轮只接纳一条正式回复 |
| 结果提交 | 数据库中的授权检查、消息、回执和去重记录使用同一写事务，提交前再次检查凭证期限 |
| 中断处理 | 核对正式消息及回执，保留已发布回复；未发布则阻塞，并保存动作摘要供后续核对 |
| 宿主退出 | 独立监护进程通过管道 EOF 检测宿主丢失，终止对应 CLI 进程组 |
| 配置生命周期 | 沿用全局 MCP 配置锁与精确还原；启动恢复不等待合法的活跃锁持有者 |
| 用量与诊断 | 常驻会话累计用量按轮作差；有界私有诊断增加执行凭证脱敏 |

正式回复仍必须通过 MCP publish_message 发布。SQLite 不能回滚原生文件
修改或远端操作，因此已交给 CLI 的请求不会因连接丢失而自动整轮重放。
主动脱离 CLI 进程组的外部任务也需要按实际资源核对。

## 验收记录

真实 CLI 在独立数据库和产物目录中完成两轮协议验收，每轮均以新凭证调用
log_thought 和 publish_message，发布内容与预期完全匹配。

| 轮次 | 场景 | 耗时 | 结果 |
| --- | --- | ---: | --- |
| 1 | 新进程及首次 MCP 调用 | 22.54 秒 | 正式回复成功入库 |
| 2 | 同进程、新任务与新凭证 | 10.86 秒 | 正式回复成功入库；原生会话及进程未变化 |

这是两轮小样本端到端结果，包含模型生成和两次 MCP 调用，不是纯启动基准，
也不能据此承诺固定提速比例。测试过程没有修改工作区源文件。

自动化检查覆盖旧凭证拒绝、跨角色隔离、并发发布去重、事务失败回滚、
超时、发布前后崩溃、空闲回收、宿主 SIGKILL、HTTP 后续任务接入和凭证脱敏。

## 启用与回退

1. 在隔离测试环境设置 `YIREN_ANTIGRAVITY_PERSISTENT=true`，通过现有团队设置启用并路由到已认证的 Antigravity。
2. 该标志仅影响真实 Antigravity 普通任务；演示模式和首次 Provider 验证保持原路径。
3. 验证连续任务的正式回复、执行凭证切换、中断记录和空闲回收。
4. 关闭该变量并正常重启可恢复每轮启动方式，历史消息及执行账本保留。

默认不开启真实模型调用。沿用单后端进程部署模型；多个独立服务不能共享
同一数据库并分别执行启动恢复。生产切换仍需负责人批准具体提交，确认
服务空闲并保留上一版本；本次 PR 不触发 Owner release 或自动部署。

## STAR 复盘

- **S（情境）**：王也执行超时后出现无回复空档；进一步实测发现每轮 CLI 初始化存在重复开销。
- **T（任务）**：在减少重复启动的同时，保证每轮身份、正式消息和中断后的任务进度可核对。
- **A（行动）**：实现受限进程复用、每轮执行凭证、事务化发布去重、持久化检查点、宿主退出监护，并补充故障注入和真实 CLI 验收。
- **R（结果）**：真实两轮使用同一进程成功发布，耗时约 22.54 秒与 10.86 秒；关键故障边界已有自动化覆盖，常驻模式可通过开关启用与回退。
