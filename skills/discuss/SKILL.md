# 讨论

给用户一份经过独立判断和复核的结果，说明建议、依据、仍有争议的部分及下一步。赞同人数不能替代验证，也不要为了展示独立性刻意反对。

## 调用与职责

用户在聊天中输入 `/discuss 议题`，宿主将其转换为 `skill="discuss"` 的任务，自动选择项目已配置的参与者，使用 `deliberation_v2` 执行。支持直接通过现有任务创建 API 传入 `{"skill":"discuss","goal":"议题"}`。参与者、模型、轮数与过程状态由宿主管理，不要求用户操作一套讨论界面。

这份技能文件在任务创建时冻结。运行中不能自行重载另一版本，参与者也不得通过 HTTP、文件、原生子 Agent 或其他工具另开讨论。开始任务、推进阶段和派发参与者由宿主负责。

## 参与讨论

- 先使用 `read_context` 读取本轮冻结输入。只有当前租约可见的材料和已经解封的结果可作为来源；按宿主要求完整读取长原文，不能把索引当作证据。
- 独立阶段先形成自己的主张、关键假设和未知，不参考同批次其他参与者的答案。宿主在全部有效提交后统一解封。
- 交流围绕会影响决定的具体分歧，给出新增证据、约束或可执行的验证方法。宿主可能只邀请与冲突 claim 相关的参与者；允许改变判断，但要说明新增依据；没有增量时按阶段 schema 提交 `no_addition=true`。
- 用户明确选择综合者后，由其整理建议、共识、分歧、待决、行动及来源。不得遗漏少数观点，不得把未经核验的事实改写成共识。
- 对每个非价值 issue，在 `issue_decisions` 中明确 `resolved`、`unresolved` 或 `deferred` 及技术决定；价值 issue 只能放入 `decisions` 交由用户选择，不得代替用户决定。
- 其他原参与者独立复核同一综合稿，检查遗漏、误读和无依据结论。没有发现时提交 `no_findings=true`；有发现时指出具体段落和期望修正，不评价综合者个人。
- 修订只处理已提交的复核问题，逐条记录处理方式。宿主最多允许一次修订，未解决的分歧或信息缺口应保留。

每轮必须使用 `submit_discussion_result` 提交符合当前阶段 schema 的对象；普通文本不算交付。成功提交后结束本轮，不追加重复总结，不输出完整内部思维过程。

## 交还用户

综合者选择、价值取舍及新条件是否重开讨论，必须由用户明确决定。界面可以只给出简短的必要选择，不能以隐藏流程为由默认替用户决定。

讨论本身不授权修改代码、执行行动项、发布结果或写入长期记忆。最终结果回到普通聊天；过程诊断可按需查看。知识候选仅在用户主动保存时创建。

阶段屏障、读取权限、轮数、停止与失败重试由程序强制执行，不能仅依赖这份提示词。若模型失败或工具拒绝提交，保留已接受结果，由宿主报告具体的脱敏错误；不要绕过权限、伪造成功或无限重试。
