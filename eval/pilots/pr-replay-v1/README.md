# AgentClub 自有 PR 回放题集

状态：已完成 17 个 PR 元数据初筛，并构建、验证了 2 道开发题。没有锁定题，没有调用模型修复，没有新增模型费用。

把历史 PR 变成题目的方式是：**还原合入前的代码，重新描述用户遇到的问题，让新的求解过程提交补丁，再独立验收。** 参考 PR 是已知可行解的来源；提交不需要与原补丁逐行一致。

## 模型能看到什么

只提供无 PR 编号的任务 ID、改写后的行为需求、基础仓库快照和统一工具。PR 原文经常包含根因、实现方案、测试名或修复提交号，不能直接当题面。

每个模型工作副本用 `git archive` 从指定 base 生成，再初始化为全新 Git 仓库：只有一个起始提交、没有远端，不继承外层工作区的 `.git` 或未来修复历史。当前选用的旧 base 不含新建的评测题集目录。未来基线如果已经包含评测目录，必须检查并清理参考解泄漏，不能自动认为归档就完成了隔离。

参考补丁、来源 PR、修复提交、验收代码及验收日志全部置于 evaluator 的 private 目录。验收在求解停止后使用另一个工作副本注入检查，不把私有测试反馈给求解者迭代。

fresh Git 历史只解决仓库历史泄漏；真实模型阶段仍须实施 private 目录访问与网络边界，避免从公开 PR 获取答案。当前准备脚本没有实现完整的模型运行隔离，因此本版还不能直接宣称盲测。

## 为什么目前都放开发集

这些历史修复已经被查看、讨论，部分由 AI 参与实现，只能诚实地用于回放型开发和探索。新 CLI session 不等于训练未见或设计阶段从未接触答案。本版不把它们标成无污染锁定集。

正式划分应按原始问题、根因、修复链和堆叠依赖分组：一个 PR 拆出的多个子题不能算多个独立问题；同一 bug 的后续补丁也不能随机分到开发和锁定两侧。例如圆桌的 #7/#8/#9 具有明显演进关系，需一起审查分区。

下一批可优先考察 #15 的失败记录展示、#8 的回合边界控制、#9 的前端交互和 #10 的追踪界面，逐个限定需求、实现独立验收并验证修复前后。它们目前是候选，尚未回放，不自动成为锁定题。已查看的同链历史题可继续扩展开发集；未来任务在解法暴露前冻结，适合建立更强的前瞻锁定集。

  --json number,title,state,mergedAt,baseRefName,headRefName,mergeCommit,additions,deletions,changedFiles,url,body \
  > output/eval/pr-corpus-v1/prs.json

  --output output/eval/pr-replay-another-run

## 与 A/B/C/D 实验的衔接

后续各组使用同一题面、基础代码、公开测试、依赖与工具权限，按同一费用和时间上限提交一份最终补丁。评分应基于独立工作副本中的行为验收和回归，而不是补丁文本相似度。

实际模型运行器还需接入：隔离的仓库读写/测试权限、最终补丁捕获、私有验收、修改测试/配置的策略检查、按需 D 和全局费用账本。这里没有启动该批次，也不把旧闭卷 Runner 当成完整 SWE 执行器。

特别区分：**被修复软件测试里产生的 MCP/A2A 事件，不算求解模型之间的真实协作。** 评测宿主的模型求助 trace 与题目测试进程的 trace 必须分开。当前 `model_calls=0`，不能把这次参考回放当作多 Agent 的能力证据。
