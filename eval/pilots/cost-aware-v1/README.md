# 成本优先的小规模异构评测

> 2026-10-19 更新：真实冒烟完成 2 题 × 6 条件，12 次最终交付通过，8 次多轮初稿也已全部通过；D 的邀请与执行均为零。本版仅完成接入/成本冒烟，真实 A2A 尚未验证。另发现工具 schema 只声明 `fire_and_forget`，与提示中的 `wait_reply` 不一致。参见[完整复盘与下一版设计](../../../docs/plans/2026-10-19-evaluation-retrospective-and-a2a-v2.md)。下文为本版原始计划，保留当时的估算与限制；新一轮不应直接照抄旧预算或 D 的回合上限。

这是一套公开的开发 pilot，用来验证真实 CLI 接入、确定性评分、协作成本与明显退化，不能承担正式模型排名或显著性结论。

本地模型检查日期：2026-10-18。模型选择由用户指定：

| 配置名 | Provider / CLI 型号 | 推理档位 |
| --- | --- | --- |
| economy | Antigravity / `gemini-3.8-flash-low` | low |
| strong | Codex / `gpt-6.1-sol` | low，运行时需显式设置 |

economy / strong 是实验配置名，不能据此认定模型能力高低。两者都选 low 是降低首轮成本的配置选择，不表示推理计算量相等。本机检测到 Codex CLI 0.162.1、Antigravity CLI 1.4.2；模型缓存与列表包含上述型号，但尚未通过本 pilot 的真实任务验证账号访问。

## 任务集

| ID | 任务 | 检查重点 |
| --- | --- | --- |
| cp-01 | 筛选待处理任务 | 简单负对照、格式遵循 |
| cp-02 | 含缓存的费用计算 | 数值正确、不重复计费；题内价格为虚构数据 |
| cp-03 | 双工位依赖排程 | 依赖顺序与资源约束 |
| cp-04 | 从变更与申请判断生效配置 | 证据优先级、避免把申请当事实 |
| cp-05 | Python 切片的零和负数边界 | 边界检查、识别不完整修复 |
| cp-06 | 缺需求量时判断工单容量 | 信息不足时保留未知 |

所有题目闭卷、只输出 JSON，无网络检索、无模型评委、无仓库大改。`json_exact` 检查完整对象、值、类型、数组顺序；对象字段顺序和空白可变。多余字段、说明文字、重复键、NaN、用字符串代替数字或把 bool 当 int 都不通过。

六题只产生六个独立样本；每类一题，没有足够证据判断某个任务类别稳定受益。代码题只检查行为理解，不能据此推导真实代码修复能力。过于容易而所有组全对时，结论是“当前题目未发现质量收益，比较成本”；不能声称能力等价。下一版本再增加有独立验收的难题，保留本版记录。

## 六个条件

| 条件 | 安排 | 每题宿主回合数 |
| --- | --- | --- |
| A-economy | Flash 直接回答 | 1 |
| A-strong | GPT 直接回答 | 1 |
| B-economy | Flash 起草、两次检查、修订 | 4 |
| B-strong | GPT 起草、两次检查、修订 | 4 |
| C-mixed | Flash → GPT → Flash → Flash | 4 |
| D-mixed | 同 C，最多插入两个动态宿主回合 | 4–6 |

三位角色保持中性人格，lead 为 `chulan`，`baobao` 使用 GPT，其他角色使用 Flash。先固定这一种成本导向配置，不试遍排列。它回答“Flash 主导、GPT 复核是否划算”，不代表已经证明所有异构组合优于同构团队。

不包含同构 C/D、独立汇总 E 或模型路由 R，故本轮不能分离身份切换、模型多样性和更多计算的全部贡献。D 也允许不触发 A2A；记录实际次数，不强迫真实模型接力。离线 fixture 特意触发 wait_reply 只为验证协议。

## 规模与分阶段停止

1. **冒烟**：cp-01 / cp-04 × 六个条件 × 一次 = 12 runs，最多 40 个宿主回合。
2. **其余题**：另外四题 × 六个条件 × 一次 = 24 runs，最多 80 个宿主回合。
3. 合计 36 runs、最多 120 个宿主回合，不自动重试、不调用 fallback、不额外重复以挑选最佳答案。

第二阶段沿用第一阶段结果，不重跑两道冒烟题。真实执行在每个 `(task, repeat)` 块内随机排列六个条件；每个 run 使用新会话。停止只基于接入失败、模型错配、缺用量或费用条件，不因为某组成绩低而跳过后续题。

## 费用口径

截至 2026-10-18 核对的标准 API 文本价格，美元 / 百万 token：

| 模型 | 输入 | 输出 | 来源 |
| --- | ---: | ---: | --- |
| GPT-6.1 Sol | 2.00 | 10.00 | [OpenAI 官方模型页](https://developers.openai.com/api/docs/models/gpt-6.1-sol) |
| Gemini 3.8 Flash | 0.75 | 3.75 | [Google 官方说明](https://ai.google.dev/gemini-api/docs/whats-new-gemini-3.8) |

这些价格用于 API 等价估算，**不代表 CLI 订阅的实际扣费**。Google 页面说明此为 2026 年底前的介绍价格；重新运行前应再次核对并冻结费率。Codex 缓存读写费率单独保存在 protocol；Flash 缓存费率尚未确认，保留 null。

准备脚本用每个宿主回合**累计**输入 12,000、累计输出 1,500 token 做规划，输出应包含已计费的推理 token，不能再重复相加。缓存折扣未应用，规划用输入基础费率；缓存写入附加费用、套餐扣费、内部隐藏调用或超出假设的用量都不能靠此表保证。

| 阶段 | API 等价规划估算 |
| --- | ---: |
| 两题冒烟 | $1.02375 |
| 剩余四题 | $2.04750 |
| 全部六题 | $3.07125 |

建议总预算 $5，其中冒烟最多分配 25%、其余题 55%、预留 20%。**$5 目前只是待用户确定的建议值**，不能当作已经授权或已经实现的硬限额。输入/输出假设也不是 API 请求的硬 token 上限。

真实运行需要保存每个模型、每个 attempt 的完整用量，包含缓存、推理与失败尝试。用量缺失标未知并暂停；不使用 `chars/3` 对异构模型计费。套餐费用未知时同时报告观测 token、耗时与标准化估算费用，实际费用留 null。

进程超时只能限制时间，不能保证美元上限。专用真实试跑入口现已在每次 CLI 调用前检查全局余额并做规划费用预留，调用后按观测用量计账；这是调用之间的软停止检查，不能直接用本文规划数充当“严格 $5 封顶”。

## 已实现与离线试跑

已落地任务文件、协议配置、严格 JSON 评分与独立参考计算。Antigravity 原生 `result.usage` 的 token、缓存与推理字段已接入流解析，按[官方输出契约](https://www.antigravity.google/docs/cli/headless/)映射；缺失不生成零用量。失败 attempt 的最终持久化与费用完整性仍需真实冒烟审计。

准备并验证（不访问模型）：

```bash
.venv/bin/python scripts/prepare_cost_pilot.py --run-fixture
```

输出到 `output/eval/cost-aware-v1/`：

- `plan.json`：六条件规模、分阶段费用估算、配置哈希与尚缺的真实运行条件。
- `scripted_answers.json`：由独立参考函数计算，仅用于链路检查。
- `fixture/`：现有 A/B/C/D runner 对六题的 24 次离线任务记录与报告，包括 D 的等待和恢复。

24 次离线运行不等于计划中的 36 次异构实验：fixture 没有访问真实模型，也没有测出不同模型的成绩。各组使用同一参考答案，满分只说明任务、评分器和流程能够接通。

## 真实运行前的最后条件

- 明确总费用上限，并决定采用 API 等价预算还是账户实际消费口径。
- 准备六个条件的隔离 Provider 配置，显式固定 model / effort / fallback。
- 补齐全局费用检查和失败 attempt 用量审计；无法观测完整费用时不得声称硬封顶。
- Agent 只获得题目，不获得本目录的 rubric、参考计算或 fixture；目前两个 CLI 默认能接触项目上下文，必须隔离。公开开发题本身仍无法保证训练未见。
- 核验原生工具、skills 与隐藏子 Agent 的权限；做不到统一限制则按“CLI 产品配置实验”解释。

本轮报告逐题列出六条件的正确性、费用来源/覆盖率、耗时和实际回合数；展示候选失败而单模型成功的退化案例。只有六题、一次重复，输出探索性对照与成本账本，不做显著性或默认路由承诺。

## 首轮真实冒烟入口

`scripts/run_cost_pilot.py` 默认只生成计划，显式 `--run` 才调用两款 CLI。当前范围固定为 cp-01 / cp-04 的 12 次任务；使用新输出目录，拒绝覆盖已有实验。

```bash
.venv/bin/python scripts/run_cost_pilot.py --run \
  --limit-usd 1.25 --timeout 120 \
  --output output/eval/real-pilot-first-run
```

专用入口固定真实 model / low effort / 无 fallback，四阶段及 A2A 沿用现有 Runner；每个 CLI 回合从空白临时目录启动，Antigravity 不再接入仓库目录。评测 MCP 服务仅暴露上下文、发言、简短判断摘要，D 另开放 invoke_agent；禁用文件交付与状态修改。Codex 的原生 sub-agent、shell、apps、plugins、hooks 等关闭；Antigravity 原生权限尚不是同样的硬允许列表，因此使用工具活动审计并按 CLI 产品配置实验解释。

Codex 的只读沙箱与 `approval_policy=never` 保持启用；临时 MCP 配置只对 `publish_message`、`log_thought`、`read_context`、`invoke_agent` 设置 `approval_mode=approve`，防止本地评测通信因缺少交互审批被拒绝。非 D 仍由服务端隐藏并拒绝 invoke_agent。没有成功发布消息但已经发生模型推理时，adapter 也会持久化观测用量，不能因回合失败漏记费用。

Antigravity 会用 `view_file` 读取自身生成的 MCP 参数 schema。审计只放行 `~/.gemini/antigravity-cli/mcp/yiren_hub/` 下精确命名的相关工具 schema；其他原生工具、其他文件路径或不足以验证的截断记录均暂停。读取 schema 的推理开销仍计费。

结果包含 `manifest.json`、`trials.jsonl`、`calls.jsonl`、`report.md`，每个任务有独立数据库和诊断记录。费用是所有输入按基础费率、输出按输出费率的统一 API 等价估算，不套用未验证的缓存折扣；缓存、推理与原始用量另外保留。任务失败、用量缺失或观察到禁止工具时暂停，答错本身不触发额外重试或删题。

协议修正必须新开目录，旧记录保留；`--prior-usd` 把前一版本的调试开销带入全局费用阈值，不能通过重开目录重置成本。空白工作目录与工具审计减少答案泄漏风险，不等于操作系统级文件隔离或完全证明服务端模型身份。
